# align — aligning a repository to the AGENTS.md contract

**Use when:** the user says "align this repo", "verstak align", "set up AGENTS.md", "update AGENTS.md", "bring this project up to standard"; unasked only in a repository marked by our cover (the door's `Start`), on the signs `references/door-start.md`, `Alignment`, names (a cover older or below this file's contract, or missing what the harness you run in needs — the door's Survey); a repository without our cover — never unasked, only on the person's word for it; a `Project` slot left `open` (round 2); an `AGENTS.md` line contradicting the method or retelling it.

**Grounding:** knowledge passed forward sits where the next session meets it and points rather than copies. `AGENTS.md` holds repository facts and the way into the graph and the door. Decisions go on nodes, the conversation in the alignment case.

You produce `AGENTS.md` (read every session), `REALITY.md` (carriers, read before a behavioural claim and in `verifier`/`reviewer` briefs), a `CLAUDE.md` pointer, the Claude Code memory guard and a quality gate; the session rituals themselves are the delivery's (Step 4). Both files are *derived views*: a projection of sources (code, manifests, CI, graph) plus thin authored judgment, held to **density** (every line changes what the agent does) and **accuracy** (every derived line re-checked against its source this run); a dense false line is worse than a verbose one.

Templates: `templates/agents-template.md` and `templates/reality-template.md`. Fill the `<…>` slots, drop optional rows that don't apply, strip every `<!-- … -->` note and angle bracket. The template carries **repository facts only** — its one mandated exception the `Refused tools` line, whose slot the run fills with the layers of the harnesses used here, by condition — Claude Code: the settings `deny`, and the plugin's hook where the plugin is loaded; OpenCode: the policy (Step 4, `The blocking question tool`); its first paragraph loads the `verstak` skill, so even a harness without a start hook reaches the door. Generic code work (before code, reviews, after merge, working principles) is `methods/code-work.md`, read through the door: never project it into `AGENTS.md`.

**Contract: `16`; the lowest still supported: `11`.** Step 7 writes the target into the `contract` field of every `AGENTS.md` cover (`15` while Step 4's live check is out of reach), with the run's date in `stamp`, after the run's checks, never in their place. A cover held at `15` that way is no unprompted full run: `references/door-start.md`, `Alignment`. Raise it by one only when a change here or in the templates makes an already generated file *wrong* (a section or file added, renamed or removed; a ritual changed; a tool name gone) — never for wording. The door's description carries the same number; a mismatch is a delivery defect (`methods/feedback.md`). **A cover ahead of the delivery is never lowered**: `contract` above `16` → no run and the number stays — update the delivery (the check below; a shadowing copy of the skill too) and re-read the door's description. How an older stamp line, a date, a hole or a `verstakify:` stamp ranks, and what another delivery's cover means — read `references/door-start.md`, `Alignment`: that repository is theirs — no unprompted run, and a run on the user's word replaces their cover and says so in its case. Below `11` — `10` and lower — a full run by current sources, not a chain of earlier moves; from `11` the moves below to `16` remain. A missing, invalid or ambiguous contract is named so, never guessed as a number. A full run keeps authored judgment and others' hooks; it wipes no config. A source this file derives from moved after `stamp` (`git log -1 --format=%cd -- <that file>`) and a line no longer matches it → that line is refreshed in your branch of work, `stamp` with it; a moved source alone is no unprompted run.

From contract 11: the memory directory takes no stub — a `MEMORY.md` stub claim in `Persistence` becomes the template's frozen-by-the-guard line, a stub file the user left stays as it is; the memory guard's refusal no longer names a stub — `prepare` rewrites a guard it wrote under the old words; one it reports `kept` that still says "prohibition stub" (an older bridge, or a guard written before `prepare` took its present form) is replaced byte for byte from `references/align-hooks.md`, `Memory guard`, the graph filled in; any other `kept` guard is the person's own; and Step 7's `Retellings → pointers` runs on the whole existing file.

From contract 12: refresh the delegation role files — each body re-projected from `references/align-delegation.md` (the restatement, the result as lines, a word only `to` someone for an answer or an act), its `Role file tails` entry kept: the old bodies prescribe a bare `say` where a person sits, which the case server is to refuse once the deliveries no longer teach it.

From contract 13: project the `deputy` role file in both harnesses from `references/align-delegation.md`, add it to `.gitignore` by name with the other eight, and give it a `Role file tails` entry where the repository's lines apply to it: a foreman hands a new case of an area to a deputy (`methods/foreman.md`, `Deputies`), and a repository aligned at `13` has no file to raise one from.

From contract 14: re-project all nine role files' bodies in both harnesses from `references/align-delegation.md`, keeping each one's model and `Role file tails` lines: a take card to a subagent is answered, not restated; the `deputy`'s case comes by a take card, its return is the subject table, and it sets no outcome for another role. A body projected at `14` restates a card by a word.

From contract 15: refuse the harness's blocking question tool (Step 4, `The blocking question tool`) — the template's `Refused tools` line into `AGENTS.md`, `AskUserQuestion` into `permissions.deny` of `.claude/settings.json`, the `question` policy into `.opencode/opencode.json` or `.jsonc` beside others' entries; which layers apply, what is N/A, and whether the cover goes to `16` or stays at `15` on a live check out of reach: Step 4, `The blocking question tool`. A file at `15` without these layers leaves the refusal to the agent's rules wherever the plugin isn't loaded.

**Own rituals**, found by content at any contract: the session rituals are the delivery's (Step 4, `The transition`). The repository's own start, push and merge hooks in `.claude/settings.json` and its rituals plugin in `.opencode/plugins/` silence the delivery; `prepare` names each in `left`; when each comes off, and what stays: Step 4, `The transition`. The cover gains `rituals:` only when the person narrows the rituals; the run never writes it (Step 7, `Cover`).

**An older cover**, found by content at any contract: the cover is the `verstak:` block of five fields (Step 7, `Cover`). Rewrite the old one into it: the `Graph` slot's rN into `graph`, the focus holon's and agent role's seqs as bare numbers into `holon` and `agent_role` (`prepare`'s `--graph`, `--holon`, `--agent-role`), this contract and today into `contract` and `stamp` (`--contract`). The start hook an older run wrote (naming the owner role) is kept by `prepare` as it stands: it comes off by Step 4, `The transition`, then run `prepare` again. Nature, Cost of breakage, Consumers, Stack, Gate, Layout, Feedback reflection and Workflow-suite interop move as values into the body's `Project` section; `Repository`, `Owner role`, `Reality`, `Agreement`, every ` — source` key and the stamp line at the file's end go. A `not agreed — case #N` source → the slot reads `open`, its question stays in the case; `agreed: <who>` lives in git and the case, not in the file.

**The support boundary and legacy content — read `references/align-migrations.md` whole before the first mutation** when the cover's `contract` is below `16`, missing, invalid or ambiguous, the cover has an older form, or the files show a `searcher` role file, a `Cross-project memory` slot, an `Agreement` or hole naming a node, or a section the template no longer has — at `16` too: the number doesn't replace the check of content. A changed counter calls an existing repository back; it does not prove that repository was re-aligned.

**Check the installed delivery first** — every run, and before concluding a method's instruction is wrong:

```
node ~/.verstak-bridge/verstak-bridge.mjs doctor          # what you are running: the bridge, each installed skill set against it
gh release view --repo verstak-ai/skills --json tagName   # what exists (doctor's "latest release" is a cache)
```

More than a patch behind → update, restart the harness sessions, then run the arc: a stale method's config inherits its defects.

## Audit → classify → act
Existence doesn't prove accuracy. Audit each concern against its source: **absent** → derive it (an authored slot without a checkable source goes to the alignment case); **stale** → re-project; **correct** → leave it. Check the *almost right* config in Step 7's accuracy pass.

### Source of truth per concern
| Concern | Source of truth | How to check |
|---|---|---|
| Versions, dependencies | `package.json` / `pyproject.toml` / `go.mod` / `Cargo.toml` + lockfile | read |
| build/test/lint/dev commands | scripts, `Makefile`/`Justfile`, CI workflow | read; `--help` or a dry run where cheap |
| Quality gate | linter config, `tsconfig`, CI yaml | read |
| Layout: code map, environment traps | the `Layout` slot in `Project` | Default: a file map in each component's README (the run writes none; meanwhile "Project structure" holds it and the first to touch the component moves it), gotchas in the graph. Where a README beside shipped outputs is forbidden, the map goes to one non-shipped file (e.g. `docs/STRUCTURE.md`) that `Project structure` points to, or stays a section while it is a few lines. An existing `GOTCHAS.md`: `open` until Step 1, files untouched |
| Project structure, path aliases | file system + bundler config; component READMEs | glob / list; the "component → README" table by the files existing |
| Nature, consumers, cost of breakage, relaxations | the graph, the code, what agents say; accepted constraints are kept | Step 1 order; changing the mandate or cost of breakage without grounds is a question of principle |
| Reality carriers (`REALITY.md`) | proposed from the graph and the delivery path the code shows; confirmed by the owner when not already recorded | the carrier is reachable; unknown → Ceiling, never an invented carrier |
| Design decisions, why-clauses, open questions | the graph — linked, not copied | `verstak_orient` / `verstak_search`, then `verstak_look` on each hit and its arrows |
| Branch state | git + forge | `git status` / `log`; the forge CLI |
| Gotchas | authored; home per `Layout` | sanity check only — don't derive or move them |
| Graph canon blocks | a rule node with `attrs.prose_for_repos` | `verstak_search(realm=<graph>, q="", attrs_filter="prose_for_repos:**")`; byte for byte where `attrs.prose_anchor` says (none → `Local overrides`), only the repo's own tail below; applicability by `attrs.scope`, else by meaning; doubt → Step 1 order |

Derived facts are re-projected every run; authored judgment (gotchas, why-clauses, nature, carriers) is kept and sanity-checked.

## Output contract — density and accuracy
1. **Imperative**: "orient before code", not "the agent should".
2. **Every line changes what the agent does**, or it goes.
3. **No rationale, no retelling of the graph, the door or a method** — link. `(why: …)` only for an invariant the agent would otherwise break.
4. **Tables and bullets**, one directive each; a section grown into paragraphs carries rationale — move it to the graph.

Orchestration mechanics (gate chains, model routing) are out of scope; delegation is role files (Step 6).

## Procedure
Idempotent: in a mature repo, run every self-check, act only on failures, report the rest.

## Two rounds
**Who runs the alignment.** The graph work — holon, role, attrs, the alignment case — is yours. The bulk file projection may go to a `designer` subagent on its own satellite bridge; none available → project it yourself. Whoever launched the run leads the alignment case. The run doesn't wait for the user to be present or confirm — except for the graph, which only the person chooses (Round 1, step 1).

**Round 1 · Stand up — no questions but the graph, under a minute, any repository.** What resolves quickly goes into the file; the rest reads `open`, its question held in the case; then round 2 without waiting.
1. **Addresses.** Graph and role from the user, the window's paste line, or an existing `AGENTS.md`. No graph named → **the graph is the person's answer, never your choice**: `verstak_realm(action="list")` and what is recorded about the repo give candidates; show the person the graphs found and `origin`, and ask — even with one candidate named like the repository. Before the answer no holon, role, case, cover or file; no person present → stop before step 2, and the hand-over says the graph waits for them. **No working graph at all**, or a repository without our cover the person asked to align (the door's Survey) → offer `methods/onboarding.md`; it runs on the person's yes and this round resumes at step 2 once it hands back. Declined or deferred → a working graph already chosen for this repository (named by the person or the paste line) → the round goes on at step 2 in it; none → the round stops before step 2, creates nothing and says so. Either way the person's other requests go on. No person present → stop before step 2; the hand-over says onboarding waits for them. Your human and the escalation role: `references/door-start.md`, `Addresses and the personal slice`; neither is written into `AGENTS.md`.
2. **The repository's holon.** `origin` → `host/org/repo` → `verstak_search(q="", node_type="holon", attrs_filter="repository:<value>")`. None → first the holon an existing `AGENTS.md` names, read by its seq: alive with no `repository` — write the attr, with a different one — as below, never overwrite; released — reviving it or a new one is the person's word, never a silent duplicate; none named → `verstak_add_holon` (`contains` from the top-level holon of the repository's area — unclear → ask the person — or top-level itself; never under one root holon: `methods/writing.md`, `Fifth: part of what?`) with `attrs.repository` and `open_room` for the alignment case. One repository, one holon. Found but the attr is missing → write it (`verstak_update`); different → don't overwrite: the same `org/repo` on another host is an alias (suggest switching `origin`; search `attrs_filter="repository:*org/repo*"`), anything else a fork or mirror — the user decides. A forge's "Not found" for the canonical name may only mean a private repo.
3. **The repository's role.** `verstak_search(q="", node_type="karta", steward_of=<holon>)`; none → `verstak_add_karta` (`manifested_as=adhikarin` — acting under a mandate; motivation distils what the repo ships) with `steward` to the holon. One role per repository.
4. **Cover and files — by the bridge, first in the round once the graph is answered, and again as steps 1–3 and 5 bring addresses** (form: Step 7):

   Without a model it writes the `verstak:` block of the front matter (`graph` rN, `holon`, `agent_role`; `contract` and `stamp` by Step 7's last call), the `REALITY.md` stub, the `CLAUDE.md` pointer, the memory guard and the blocking question tool's two project layers beside others' entries (Step 4, `The blocking question tool`); what stands is not overwritten. A holon and role no flag names it reads from the graph by `origin` when the bridge holds a key (the answer's `derived`). Exit 3 → the answer's `left` is yours; exit 0 → nothing left; exit 1 → refused, nothing written: its reason goes into the case. The answer not JSON (an older bridge) → the fallback: the cover by the template and Step 7, the guard by Step 4. An older cover is rewritten into the block on the same move (`An older cover`; `prepare` leaves it as `cover.flat`). A memory guard the repository runs from a script of its own gets no second from `prepare`: it reads the script and keeps one it recognises; any other script on a `PreToolUse` matcher covering Write and Edit it names in `left` — read that script; it is the guard → nothing to do; it isn't → add ours by Step 4. A name in the cover's `rituals:` the delivery doesn't know comes back as `cover.rituals`: fix it or drop it. Judgment slots go into the body's `Project`: from the graph, the code or a recorded answer (a neighbouring holon's agent included) → the value; unresolved → `open`, its question in the alignment case. ### Step 1 — Resolve the slots
Read the graph, the code and the old config; don't pick defaults silently. Write into `Project` **Nature** (not `production` → what is relaxed and why), `Stack`, the **gate**; the **graph** into the cover. Keep accepted authored constraints. The user is usually absent, so every "agree / ask / confirm" means:
1. **Do everything that doesn't depend on the answer** — audit, derivable facts, gate, hooks.
2. **Graph and code, then sibling agents of neighbouring holons.** What stays open is a message in the one alignment case, never a node or a case per slot: `verstak_case(action="invite")` those who know and put the question to them as an `ask` card (the door, `Waiting on an answer`).
3. **Only the residue of principle goes to the user, through the case lead**: changing the mandate, an accepted constraint or the cost of breakage; choosing or creating the graph; confirming a reality carrier not already recorded; a source conflict you can't resolve. A missing answer alone is not. Nobody but the person to ask (a new graph, no neighbours) → what can't be derived goes to them as an `ask` card in the case — never a guess. Name what you checked and whom you asked. The lead asks the same way: the card to their seat, no seat → to their role (`karta=<your human's role>`), self-sufficient, with no word beside it (`methods/collaborate.md`, `Asking the user`); never an `invite` of the user into the case; nothing reachable → the card waits in the case, the work goes on.
4. **`open`, not a guess**: the slot reads `open`, its question stays in the alignment case.

Write each answer at once; slots don't wait for each other.

**Old questionnaire** — an older cover's `Agreement` or a hole naming a node (`#N`), at any contract → `references/align-migrations.md`, `Old questionnaire`, read before the slot is touched.

Also settle:
- **Shared mutable build/test state** (database, fixed port, dev server, global cache, cloud sandbox) → per-lane isolation as gotchas: agents run branches concurrently in separate worktrees.
- **Reality** → `REALITY.md`. Push each claim class to its *canonical carrier* (the built artifact, not the sources; the live endpoint, not the handler). Recorded in the graph or a named answer → write it; new → propose it in the alignment case and write the row with `(proposed — case #N)` after its class until the owner confirms. No reachable observation → *Ceiling* with the reason. `AGENTS.md` gets a "Reality" pointer naming the first row.
- **No personal memory in `AGENTS.md`** — no slot, no rule: where the user's own lives and when it is read are the door's (the start slice) and `methods/minding.md`'s. Establish personal memory through minding's entry (`realm="mind"`). Never construct or persist its address, create or ask about a global instructions file.
- **Feedback reflection** (`methods/feedback.md`) — default **yes**, no question; **no** only on a recorded answer. The slot is all you write: `methods/code-work.md`, `After merge`, reads it.
- **Workflow suite** — only when a coercive one is found (its skills or plugin-cache directory; today superpowers): **full interop** (recommended: `references/align-superpowers-interop.md` plus the spec-write hook), **prose only**, or **skip** — its design sessions won't reach the graph.

### Step 2 — Bootstrap the graph
- The focus holon is the project boundary: design it with `methods/design.md` before round 1's `verstak_add_holon`; its `repository` attr (form: Round 1, step 2) is set on creation and refresh.
- **No working graph** → never `verstak_realm(action="create")` from here: Round 1, step 1's onboarding branch.
- **The agent role is the steward** of the focus holon — not a senior role, or orienting on the holon won't find who acts there. The holon's seq goes into the cover's `holon`, the agent role's into `agent_role`; the role belongs to the repository, not to a person (`references/door-start.md`, `Addresses and the personal slice`): its `group` arrow, if any, leads to a senior agent role. A `group` arrow from it to a person's role found in the graph is left as it stands, never added, and named in the alignment case.
- Every arrow gets a `sense`, so the next reader grasps this corner without opening the repo.
- **Holon + steward are the root of the integration scope** (`methods/code-work.md`, `Before code`); `AGENTS.md` lists no shared surfaces but a consumer no arrow reaches (Step 7, in `Local overrides`).

### Step 3 — Quality gate (the strictest the accepted mandate allows)
No code in the repository (texts only) → no stack: `Stack` and `Gate` read `none — no code` (derived from the repository, not `open`), no gate is set, and no tool is picked by the runtime of the harness or a plugin. Per item: the strictest option for the stack, the trade-off in one line, the source per Step 1. A relaxation needs an accepted constraint calibrated by cost of breakage, recorded in `Project` per tool; no grounds → a question of principle. **Tightening** a relaxed gate: measure first (run at the proposed strictness, count failures); it may go as a separate branch.
- **Linter**, strictest (`@typescript-eslint/strict`; Ruff `E,F,B,I,N,UP,RUF`; broad `golangci-lint`; `clippy -- -D clippy::pedantic`).
- **Formatter**, auto-fix (Prettier, `ruff format`, `gofumpt`, `rustfmt`); **type checker** strict (`tsc --strict`, `mypy --strict` / `pyright --strict`); all three in a pre-commit hook on staged files.
- **Tests** (unit for libraries; + integration for services; + e2e for UI; coverage threshold for production) → "Code conventions". Name how the gate runs only the affected modules and their direct compositions and reuses results by content (`methods/code-work.md`, `Tests and CI`); missing → say so in the slot and close the gap in the batch, unless an explicit exception from the rule's principal covers this repository. Record its scope in `Local overrides`; measuring cost is evidence for a request, not permission.
- **CI**: the gate on the batch's PR and on trunk (`methods/code-work.md`, `Tests and CI`), failing on warnings; mandatory for `production`. Read the triggers from the CI yaml; don't write the slot from the rule.
- **The gate is one call** (`npm run gate`, `make check`, `just check`); `AGENTS.md` names it, CI calls the same. A hand-assembled gate drops a step and still ends green; if unavoidable, record why and what checks its completeness.
- **CI parity**: every check that can fail gates the PR (codegen, schema/doc generation, image build, migrations); an irreducible gap is a gotcha.

### Step 4 — Hooks
**The delivery carries the rituals, not the working tree.** The Claude Code plugin's hooks and the delivered OpenCode plugin speak from the cover: the start word (full where the block names `holon` and `agent_role`, else the onboarding's early word), push and merge by outcome (`methods/code-work.md`, `Cold review` and `After merge`), in OpenCode the memory guard too, on a watch the turn's end word (`methods/autonomous.md`, `5 · Escalation`); a push whose target names `main` or `master` gets the merge word, under the `push` switch, not `merge`; a quiet push naming no trunk from a folder on `main` or `master` gets neither; a non-zero exit silences the push only when the push is last in the chain and git printed no report; behind a pipe the exit is hidden. The run writes none of them — unless no delivery carries them for a harness of this repository: the skill installed without the plugin, or a delivery older than this contract (how to tell: the transition below) → wire that harness's rituals by hand from `references/align-hooks.md` (Claude Code) or `references/align-harness-surfaces.md` (OpenCode) and say so in the report; they come off once the delivery catches up. Codex and pi get no hooks: `AGENTS.md`'s opening paragraph and `methods/code-work.md` carry the rituals there. Which speak is the cover's `rituals:` field (`start push merge guard turn`; no field — all, empty — none): the person's choice, never written by the run.

**The Claude Code memory guard is the repository's hook** while `guard` is on (turned off in `rituals:` → take the hook off): `prepare` writes it into `.claude/settings.json` (Round 1, step 4), committed. **Merge, never overwrite** — other suites' entries stay. Without the bridge, copy it **byte for byte from `references/align-hooks.md`**, `Memory guard`. Its refusal names the project graph and this `AGENTS.md`'s persistence section and routes personal content through minding's entry without a personal address; a bare ban or a constructed mind locator is a projection defect. A harness flagging the write as self-modification: write anyway, name it, read back that it landed.

**The blocking question tool is refused, never a ritual** (why: `methods/collaborate.md`, `Asking the user`): no `rituals:` value turns a layer off, and each layer stands on its own. **Ours** here means a mark in `AGENTS.md` — our `verstak:` cover, its older flat keys or our stamp line, never another delivery's cover; a start hook or rituals plugin alone marks nothing (`references/door-start.md`, `Alignment`). **Each layer counts only where its harness is used**; one that isn't is N/A in the report and the live check; which harness is used here, `references/align-harness-surfaces.md`, `Detect`. `prepare` writes both project layers whatever the harness, inert where it isn't used; by hand, only those that apply. Claude Code used → `"AskUserQuestion"` in `permissions.deny` of `.claude/settings.json`, added by merge, others' `allow`, `deny` and fields kept, committed; where the plugin is loaded, also its `PreToolUse` hook — it denies `AskUserQuestion` in a repository of ours whatever its `rituals:`, and in any other repository says nothing; nothing of it is written here. OpenCode used → the project policy `{"action":"tool.use","resource":"question:*","effect":"deny"}` in `policies` of `.opencode/opencode.json`, merged by `prepare`, or of a single `.opencode/opencode.jsonc` already holding it, which `prepare` accepts without a write; a JSONC without it, one that doesn't parse, or JSON and JSONC side by side → `prepare` refuses, rewrites neither and writes no second config, naming the file: fix it by hand, every comment kept, and rerun; no higher-precedence policy allowing `tool.use` on `question`. Where the delivered OpenCode plugin is loaded, it also removes `question` and refuses its permission in a repository of ours, and in any other leaves the tool and the permission decision as they were; nothing of it is written here.
