# Derivation map — the method ← methodology canon

The single `verstak` skill is the **portable projection** of the methodology
realm: canon lives in the graph, the delivery carries its agent-facing summary
inline. Its source is `skills/verstak/`: the door `SKILL.md`, `methods/*.md`,
`references/*.md` and `templates/*.md`. These files are realm-agnostic and may not
point into the maintainer's graph — see AGENTS.md conventions. Drift is therefore
structural: when a canon landmark changes, projected sections do NOT update
themselves. This map is the maintainer's re-projection checklist.

**Ritual:** after any push that changes a methodology canon landmark, walk its row:
re-project each listed section from the landmark's current body, run `make check`,
review the diff. The same audit-classify-act discipline `methods/align.md` applies
to AGENTS.md, applied to the delivery.

This file is maintainer-facing (realm access assumed); graph seqs are allowed here,
but forbidden inside `skills/`. Unqualified seqs below belong to methodology;
`nks-dev` seqs are development decisions or observations, not canon by promotion.
Paths in the tables are relative to `skills/verstak/`; quoted targets are actual
headings, with a step or paragraph specified where the heading is broader.

The sibling delivery's map is a coverage checklist, not a source of English
instructions. Check every target against the shipped file. A removed projection
is marked **not projected — cut in the port**, not assigned an invented heading.
Targets belonging only to the sibling delivery's methodology-editing method are
outside this delivery and omitted.

## Extra sync obligations

- **Tool surface → delivery** (AGENTS.md: tool references must be live): when
  nks-mcp renames or drops a tool, or changes factory behaviour, search
  `skills/verstak/` for its `verstak_*` name. Names and enums are checked against
  `fixtures/surface.json`; behavioural claims still need observation and review.
- **superpowers → interop**: `references/align-superpowers-interop.md` →
  "Re-verify checklist (maintainers only, on a superpowers upgrade)" carries the
  checklist. Harness and role-file changes also require the maintainer checklists
  in `references/align-harness-surfaces.md` and `references/align-delegation.md`.
- **Human bridge → collaborate**: the address-line contract is duplicated across
  deliveries; if its fields change, re-project `methods/collaborate.md` →
  "Incoming — what arrived, where to answer" in the same move.
- **Method file → graph model**: each changed method has both an artifact
  phenomenon and an applying kriya, decomposed into protocol phases with tool
  edges and composition links. Keep both halves and their steps in correspondence
  with the shipped file (AGENTS.md); a summary paragraph is not that model.
- **Source → bundle**: changes under `skills/verstak/` require `make build`;
  `verstak.skill` and installed copies are derived, never the re-projection source.

## Product departs from canon (deliberately)
The skill keeps the product rule and does not annotate it; re-decide here when either side moves.

1. **Main reading and ledger — resolved, no longer a departure.** The door now follows r4 #744: a case is read first by its ledger summary (latest `[was] [did] = verdict` per subject, verdict on observed outcomes), the snapshot of the work in progress; the lasting result lives in the graph (modes, nodes, arrows), and a closed case is dropped. The owner's word: the summary is the case's main reading; state and effect stay in the graph.
2. **Every subagent assignment gets a child case:** the door requires a new child case. r4 #745 allows the launching agent's own case, a child case, or the case of the particular work. The product deliberately narrows that choice; unchanged.
3. **Closure procedure:** architect/autonomous use the surface's `ends_at` objection deadline and participant eligibility. r4 #747 makes journal order before the final closure entry decisive and continues late substance in a new case. Exact calls remain unchanged; the skills now state the canon's receiving/could-object condition rather than treating every silent participant as consenting.
