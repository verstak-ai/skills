# align — aligning a repository to the AGENTS.md contract

**Use when:** the user says "align this repo", "verstak align", "set up AGENTS.md", "update AGENTS.md", "bring this project up to standard"; unasked, at `door-start`, `Alignment`: `AGENTS.md` missing in a repository bearing a sign of alignment, its cover's `contract` missing or below this file's contract, the cover still in an older form; a repository bearing a sign of alignment but missing what the harness you run in needs (`verstak`'s Survey: Claude Code and OpenCode — a cover naming `graph`, `holon` and `agent_role`, from which the delivery's plugin speaks the start, or a start hook of the repository's own; Codex and pi — cover and stamp only); a `Project` slot left `open` (round 2); an `AGENTS.md` line contradicting the method or retelling it.

**Grounding:** knowledge passed forward sits where the next session meets it and points rather than copies. `AGENTS.md` holds repository facts and the way into the graph and `verstak`. Decisions go on nodes, the conversation in the alignment case.

You produce `AGENTS.md` (read every session), `REALITY.md` (carriers, read before a behavioural claim and in `verifier`/`reviewer` briefs), a `CLAUDE.md` pointer, the Claude Code memory guard and a quality gate; the session rituals themselves are the delivery's (Step 4). Both files are *derived views*: a projection of sources (code, manifests, CI, graph) plus thin authored judgment, held to **density** (every line changes what the agent does) and **accuracy** (every derived line re-checked against its source this run); a dense false line is worse than a verbose one.

Templates: `agents-template` and `reality-template`. Fill the `<…>` slots, drop optional rows that don't apply, strip every `<!-- … -->` note and angle bracket. The template carries **repository facts only**; its first paragraph loads the `verstak` skill, so even a harness without a start hook reaches `verstak`. Generic code work (before code, reviews, after merge, working principles) is **code-work**, read through `verstak`: never project it into `AGENTS.md`.

**Contract: `11`.** Step 7 writes it into the `contract` field of every `AGENTS.md` cover, with the run's date in `stamp`. Raise it by one only when a change here or in the templates makes an already generated file *wrong* (a section or file added, renamed or removed; a ritual changed; a tool name gone) — never for wording. `verstak`'s description carries the same number; a mismatch is a delivery defect (**feedback**). An older stamp line (`verstak align: contract N` at the file's end) carries a contract below `10`; a date, no cover or stamp at all, or a `verstakify: contract N` stamp ranks as `door-start`, `Alignment` says; another delivery's cover block or stamp with none of ours means the repository is that delivery's — no unprompted run, and a run on the user's word replaces their cover and says so in its case. A source this file derives from moved after `stamp` (`git log -1 --format=%cd -- <that file>`) and a line no longer matches it → that line is refreshed in your branch of work, `stamp` with it; a moved source alone is no unprompted run.

From contract 10: the session rituals move to the delivery (Step 4, `The transition`). Take off the repository's own start, push and merge hooks in `.claude/settings.json` and its rituals plugin in `.opencode/plugins/` — beside them the delivery keeps silent; `prepare` names each in `left`. The Claude Code memory guard stays in the tree. The cover gains `rituals:` only when the person narrows the rituals; the run never writes it (Step 7, `Cover`).

From contract 9: the cover becomes the `verstak:` block of five fields (Step 7, `Cover`). Rewrite the old one into it: the `Graph` slot's rN into `graph`, the focus holon's and agent role's seqs as bare numbers into `holon` and `agent_role` (`prepare`'s `--graph`, `--holon`, `--agent-role`), this contract and today into `contract` and `stamp` (`--contract`). The start hook an older run wrote (naming the owner role) is kept by `prepare` as it stands: remove it, then run `prepare` again. Nature, Cost of breakage, Consumers, Stack, Gate, Layout, Feedback reflection and Workflow-suite interop move as values into the body's `Project` section; `Repository`, `Owner role`, `Reality`, `Agreement`, every ` — source` key and the stamp line at the file's end go. A `not agreed — case #N` source → the slot reads `open`, its question stays in the case; `agreed: <who>` lives in git and the case, not in the file.

From contract 8: the delegation roles are eight (Step 6). Project `weaver`, `recaller` and `ingester` in both harnesses and add them to `.gitignore` by name; delete both of your own `searcher` files and drop them from `.gitignore` (graph search is now `recaller`, for the recall ladder); re-project `designer`'s body, which no longer writes the graph — the volume edit of touched nodes is `weaver`'s, a story's intake `ingester`'s. Each file's tail in `Role file tails` carries over; a `searcher` tail goes to `recaller` where it still applies, else is named in the report.

From contract 7: your six role files leave the index and go into `.gitignore` by name — the files stay on disk, others' agents untouched (Step 5); every other clone loses them on its next pull, so say it in the alignment case and the PR body: a receiving copy saves its role files before pulling and puts them back (they are ignored then), else re-projects them by Step 6; each file's repository tail moves into `AGENTS.md`, section `Role file tails`, and its model comes from the person's preferences (Step 6). Branch worktrees live inside the repository, in `.worktrees/` (ignored); abandoned trees and your trees' development caches are cleaned up (**code-work**, `Branch and worktree`, `Cleanup`). Re-project `Git workflow` and `Persistence` from the template, and the tracked-secrets line of `Code conventions` (untrack and rotate; `skip-worktree` hides nothing).

From contract 6: the git and test rituals changed — one branch and PR per batch, review by the batch's tier, CI on the batch's PR and trunk, tests by the affected. Re-project `Git workflow` and `Test discipline` from the template; a line promising CI on every push, a light review on every finished branch, or a branch per item goes. Keeping a full gate instead of selection needs an explicit, applicable exception from the rule's principal in `Local overrides`; a cost measurement alone grants none. Re-project the push hook's text (Step 4) and the `reviewer` role body (`align-delegation`) above `## This repo`.

From contract 5: drop the cover's `Cross-project memory` slot and its source line — personal memory has no place in `AGENTS.md`.

From contract 4: re-project memory routing and guard messages through minding, with no constructed or stored personal address; refresh the ritual and delegation projections against their current references too. A changed counter calls an existing repository back; it does not prove that repository was re-aligned.

**Check the installed delivery first** — every run, and before concluding a method's instruction is wrong:

More than a patch behind → update, restart the harness sessions, then run the arc: a stale method's config inherits its defects.

## Audit → classify → act
Existence doesn't prove accuracy. Audit each concern against its source: **absent** → derive it (an authored slot without a checkable source goes to the alignment case); **stale** → re-project; **correct** → leave it. Check the *almost right* config in Step 7's accuracy pass.

### Source of truth per concern
| Concern | Source of truth | How to check |
|---|---|---|
| Versions, dependencies | `package.json` / `pyproject.toml` / `go.mod` / `Cargo.toml` + lockfile | read |
| build/test/lint/dev commands | scripts, `Makefile`/`Justfile`, CI workflow | read; `--help` or a dry run where cheap |
| Quality gate | linter config, `tsconfig`, CI yaml | read |
| Layout: code map, environment traps | the `Layout` slot in `Project` | Default: a file map in each component's README (the run writes none; meanwhile "Project structure" holds it and the first to touch the component moves it), gotchas in the graph. A section *instead of* READMEs only where a README beside shipped outputs is forbidden. An existing `GOTCHAS.md`: `open` until Step 1, files untouched |
| Project structure, path aliases | file system + bundler config; component READMEs | glob / list; the "component → README" table by the files existing |
| Nature, consumers, cost of breakage, relaxations | the graph, the code, what agents say; accepted constraints are kept | Step 1 order; changing the mandate or cost of breakage without grounds is a question of principle |
| Reality carriers (`REALITY.md`) | proposed from the graph and the delivery path the code shows; confirmed by the owner when not already recorded | the carrier is reachable; unknown → Ceiling, never an invented carrier |
| Design decisions, why-clauses, open questions | the graph — linked, not copied | `verstak_orient` / `verstak_search`, then `verstak_look` on each hit and its arrows |
| Branch state | git + forge | `git status` / `log`; the forge CLI |
| Gotchas | authored; home per `Layout` | sanity check only — don't derive or move them |
| Graph canon blocks | a rule node with `attrs.prose_for_repos` | `verstak_search(realm=<graph>, q="", attrs_filter="prose_for_repos:**")`; byte for byte where `attrs.prose_anchor` says (none → `Local overrides`), only the repo's own tail below; applicability by `attrs.scope`, else by meaning; doubt → Step 1 order |

Derived facts are re-projected every run; authored judgment (gotchas, why-clauses, nature, carriers) is kept and sanity-checked.

## Output contract — density and accuracy
1. **Imperative**: "orient before code", not "the agent should".
2. **Every line changes what the agent does**, or it goes.
3. **No rationale, no retelling of the graph, `verstak` or a method** — link. `(why: …)` only for an invariant the agent would otherwise break.
4. **Tables and bullets**, one directive each; a section grown into paragraphs carries rationale — move it to the graph.

Orchestration mechanics (gate chains, model routing) are out of scope; delegation is role files (Step 6).

## Procedure
Idempotent: in a mature repo, run every self-check, act only on failures, report the rest.

## Two rounds
**Who runs the alignment.** The graph work — holon, role, attrs, the alignment case — is yours. The bulk file projection may go to a `designer` subagent on its own satellite bridge; none available → project it yourself. Whoever launched the run leads the alignment case. The run doesn't wait for the user to be present or confirm.

**Round 1 · Stand up — no questions, under a minute, any repository.** What resolves quickly goes into the file; the rest reads `open`, its question held in the case; then round 2 without waiting.
1. **Addresses.** Graph and role from the user, the window's paste line, or an existing `AGENTS.md`. No graph named → `verstak_realm(action="list")`, what is recorded about the repo, colleagues; still unclear → a question of principle, never a guessed name. **No working graph at all**, or none of the three signs of alignment (`verstak`'s Survey) → offer **onboarding**; it runs on the person's yes and this round resumes at step 2 once it hands back. Declined or deferred → a working graph already chosen for this repository (named by the person or the paste line) → the round goes on at step 2 in it; none → the round stops before step 2, creates nothing and says so. Either way the person's other requests go on. No person present → stop before step 2; the hand-over says onboarding waits for them. The owner role is found by `verstak`'s rule (`door-start`, `Addresses and the personal slice`): where the agent role's `group` arrow leads; no arrow yet → the `svatantra` role of the person whose keys you hold (`verstak_me(action="kartas")`) when they answer for this repository — a list showing roles you yourself stand in means the binding is off, ask in the case — and that answer is laid as the agent role's `group` arrow (step 2). The owner role is not written into `AGENTS.md`: it lives in the graph and is addressed by its seq, never `me`. `kartas` sees only bound roles, so before creating one look for a role made for the person in advance and bind it on their word as **onboarding**, step 3, says — one rule for both methods. A role is the person's by its user binding, never a handle, name or attribute match; can't tell → one question to the session's user, or the alignment case when they are absent.
2. **The repository's holon.** `origin` → `host/org/repo` → `verstak_search(q="", node_type="holon", attrs_filter="repository:<value>")`. None → `verstak_add_holon` (`contains` from the root or the repositories holon) with `attrs.repository` and `open_room` for the alignment case. One repository, one holon. Found but the attr is missing → write it (`verstak_update`); different → don't overwrite: the same `org/repo` on another host is an alias (suggest switching `origin`; search `attrs_filter="repository:*org/repo*"`), anything else a fork or mirror — the user decides. A forge's "Not found" for the canonical name may only mean a private repo.
3. **The repository's role.** `verstak_search(q="", node_type="karta", steward_of=<holon>)`; none → `verstak_add_karta` (`manifested_as=adhikarin` — acting under a mandate; motivation distils what the repo ships) with `steward` to the holon. One role per repository.
4. **Cover and files — by the bridge, first in the round and again as steps 1–3 and 5 bring addresses** (form: Step 7):
   ```
   node ~/.verstak-bridge/verstak-bridge.mjs prepare --json [--graph rN --holon N --agent-role N --case N] </dev/null
   ```
   Without a model it writes the `verstak:` block of the front matter (`graph` rN, `holon`, `agent_role`; `contract` and `stamp` by Step 7's last call), the `REALITY.md` stub, the `CLAUDE.md` pointer and the memory guard beside others' entries; what stands is not overwritten. A holon and role no flag names it reads from the graph by `origin` when the bridge holds a key (the answer's `derived`). Exit 3 → the answer's `left` is yours; exit 0 → nothing left; exit 1 → refused, nothing written: its reason goes into the case. The answer not JSON (an older bridge) → the fallback: the cover by the template and Step 7, the guard by Step 4. An older cover is rewritten into the block on the same move (`From contract 9`; `prepare` leaves it as `cover.flat`). A memory guard the repository runs from a script of its own gets no second from `prepare`: it reads the script and keeps one it recognises; any other script on a `PreToolUse` matcher covering Write and Edit it names in `left` — read that script; it is the guard → nothing to do; it isn't → add ours by Step 4. A script on `SessionStart` it can't read is named the same way: it is a start hook → take it off (Step 4, `The transition`); it isn't → nothing to do. A name in the cover's `rituals:` the delivery doesn't know comes back as `cover.rituals`: fix it or drop it. Judgment slots go into the body's `Project`: from the graph, the code or a recorded answer (a neighbouring holon's agent included) → the value; unresolved → `open`, its question in the alignment case. The user being away doesn't make an authored slot `open`. Until carriers are resolved, `REALITY.md` holds the template heading and "Carriers not yet established; alignment case #N. Until they are, behavioural claims are not accepted." — the stub `prepare` writes with `--case N`.
5. **The alignment case** on the holon: an open one (`verstak_case(action="at", node=<holon>)`) → lead it; none → `open_room` on the holon's write or a `verstak_update` of it, titled in at most 64 characters: "Align <repo> to contract N". Take your seat under the repository role and join before your first entry (`verstak`, Survey). `designer` gets a child case (`open_room` with `parent_room`) in its launch line; its conduct is its role body (`align-delegation`). First message: "I have questions about the project I'm responsible for — answer them, or tell me who can." **The questionnaire, plan and progress never go into the graph** — only structure (holon, role) and gotchas as rules.
6. **Of Step 4, only the memory guard**, written by step 4's `prepare` — the other rituals the delivery speaks from the cover; the `MEMORY.md` stub only over an empty or missing memory directory — a non-empty one waits for round 2 (Step 5), the freeze line pointing at the case meanwhile.

Report in the alignment case (resolved, open) — also when started from another case, naming it there. Then the Step 7 handover.

**Round 2 · Finish — on your own, without blocking.** Each later start reads the holon's alignment case as `door-start`, `Alignment` says and resolves slots in Step 1 order without re-asking. An agent's answer is signed with its name, not re-confirmed by the user. The full arc (Steps 1, 3–6) runs without the user; an unresolved slot holds only what depends on it. All resolved → `propose_close` with the filled `Project` slots and who answered as evidence if you lead; else a message to the lead.

### Step 1 — Resolve the slots
Read the graph, the code and the old config; don't pick defaults silently. Write into `Project` **Nature** (not `production` → what is relaxed and why), `Stack`, the **gate**; the **graph** into the cover. Keep accepted authored constraints. The user is usually absent, so every "agree / ask / confirm" means:
1. **Do everything that doesn't depend on the answer** — audit, derivable facts, gate, hooks.
2. **Graph and code, then sibling agents of neighbouring holons.** What stays open is a message in the one alignment case, never a node or a case per slot: `verstak_case(action="invite")` those who know and `say` the question.
3. **Only the residue of principle goes to the user, through the case lead**: changing the mandate, an accepted constraint or the cost of breakage; choosing or creating the graph; confirming a reality carrier not already recorded; a source conflict you can't resolve. A missing answer alone is not. Nobody but the person to ask (a new graph, no neighbours) → what can't be derived goes to them as an `ask` card in the case and a word to their seat — never a guess. Name what you checked and whom you asked. The lead `invite`s the user's seat; no seat → their role with the holon (`karta=<owner role>`, `holon=<repository holon>`); nothing reachable → the question waits, the work goes on.
4. **`open`, not a guess**: the slot reads `open`, its question stays in the alignment case.

Write each answer at once; slots don't wait for each other.

**Old questionnaire.** An older cover's `Agreement` or hole names a node (`#N`) → `verstak_look`: answers → `Project` values; open ones → `open`, the question a message in the case. Release the node (`visarjana`, reasoning "moved to case #N"); not yours → message its author.

Also settle:
- **Shared mutable build/test state** (database, fixed port, dev server, global cache, cloud sandbox) → per-lane isolation as gotchas: agents run branches concurrently in separate worktrees.
- **Reality** → `REALITY.md`. Push each claim class to its *canonical carrier*: the built artifact, not the sources; the live endpoint, not the handler; a clean install, not a warm cache. Recorded in the graph or a named answer → write it; new → propose it in the alignment case and write the row with `(proposed — case #N)` after its class until the owner confirms. No reachable observation → *Ceiling* with the reason. `AGENTS.md` gets a "Reality" pointer naming the first row.
- **No personal memory in `AGENTS.md`** — no slot, no rule: where the user's own lives and when it is read are `verstak`'s (the start slice) and **minding**'s; an older cover's personal-memory slot and its source line go on this run. Establish personal memory through minding's entry (`realm="mind"`). Never construct or persist its address, create or ask about a global instructions file.
- **Feedback reflection** (**feedback**) — default **yes**, no question; **no** only on a recorded answer. The slot is all you write: **code-work**, `After merge`, reads it.
- **Workflow suite** — only when a coercive one is found (its skills or plugin-cache directory; today superpowers): **full interop** (recommended: `align-superpowers-interop` plus the spec-write hook), **prose only**, or **skip** — its design sessions won't reach the graph.

### Step 2 — Bootstrap the graph
- The focus holon is the project boundary: design it with **design** before round 1's `verstak_add_holon`; its `repository` attr (form: Round 1, step 2) is set on creation and refresh.
- **No working graph** → never `verstak_realm(action="create")` from here: **onboarding** asks the area, continues a graph the person was invited to, creates one only on their word, then hands back.
- **The agent role is the steward** of the focus holon — not a senior role, or orienting on the holon won't find who acts there. No owner role found → **onboarding**, step 3: registered by the person's own name without a question, bound to them, renamed later on their word. The holon's seq goes into the cover's `holon`, the agent role's into `agent_role`; the owner role stays in the graph as the agent role's `group` arrow to it (`door-start`, `Addresses and the personal slice`) — laid when align creates the agent role, or added when it finds one without it.
- Every arrow gets a `sense`, so the next reader grasps this corner without opening the repo.
- **Holon + steward are the root of the integration scope** (**code-work**, `Before code`); `AGENTS.md` lists no shared surfaces.

### Step 3 — Quality gate (the strictest the accepted mandate allows)
No code in the repository (texts only) → no stack: `Stack` and `Gate` read `none — no code` (derived from the repository, not `open`), no gate is set, and no tool is picked by the runtime of the harness or a plugin. Per item: the strictest option for the stack, the trade-off in one line, the source per Step 1. A relaxation needs an accepted constraint calibrated by cost of breakage, recorded in `Project` per tool; no grounds → a question of principle. **Tightening** a relaxed gate: measure first (run at the proposed strictness, count failures); it may go as a separate branch.
- **Linter**, strictest (`@typescript-eslint/strict`; Ruff `E,F,B,I,N,UP,RUF`; broad `golangci-lint`; `clippy -- -D clippy::pedantic`).
- **Formatter**, auto-fix (Prettier, `ruff format`, `gofumpt`, `rustfmt`); **type checker** strict (`tsc --strict`, `mypy --strict` / `pyright --strict`); all three in a pre-commit hook on staged files.
- **Tests** (unit for libraries; + integration for services; + e2e for UI; coverage threshold for production) → "Code conventions". Name how the gate runs only the affected modules and their direct compositions and reuses results by content (**code-work**, `Tests and CI`); missing → say so in the slot and close the gap in the batch, unless an explicit exception from the rule's principal covers this repository. Record its scope in `Local overrides`; measuring cost is evidence for a request, not permission.
- **CI**: lint + type check + tests on the batch's PR and on trunk, not on every branch push, failing on warnings; mandatory for `production`. Read the triggers from the CI yaml; don't write the slot from the rule.
- **The gate is one call** (`npm run gate`, `make check`, `just check`); `AGENTS.md` names it, CI calls the same. A hand-assembled gate drops a step and still ends green; if unavoidable, record why and what checks its completeness.
- **CI parity**: every check that can fail gates the PR (codegen, schema/doc generation, image build, migrations); an irreducible gap is a gotcha.

### Step 4 — Hooks
**The delivery carries the rituals, not the working tree.** The Claude Code plugin's hooks and the delivered OpenCode plugin speak from the cover's `graph`: the start word — full where the block also names `holon` and `agent_role` (load the `verstak` skill first, every session, and do `verstak`'s `Start` with those addresses), else the onboarding's early word; push and merge by outcome (**code-work**, `Cold review` and `After merge`; a push whose target names `main` or `master` gets the merge word, under the `push` switch, not `merge`; a quiet push naming no trunk from a folder on `main` or `master` gets neither; a non-zero exit silences the push only when the push is last in the chain and git printed no report; behind a pipe the exit is hidden and a quiet push may still get a word); in OpenCode the memory guard too; on a watch, a turn begun by a frame addressed to the seat that ended in console text is woken once — not a short receipt with no question, nor while the user wrote in this session within 30 minutes (**autonomous**, `5 · Escalation`). The run writes none of them — unless no delivery carries them for a harness of this repository: the skill installed without the plugin, or a delivery older than this contract (how to tell: the transition below) → wire that harness's rituals by hand from `align-hooks` (Claude Code) or `align-harness-surfaces` (OpenCode) and say so in the report; they come off once the delivery catches up. Codex and pi get no hooks: `AGENTS.md`'s opening paragraph and **code-work** carry the rituals there. Which speak is the cover's `rituals:` field (`start push merge guard turn`; no field — all, empty — none): the person's choice, never written by the run.

**The Claude Code memory guard is the repository's hook** while `guard` is on (the hook reads no field — turned off in `rituals:`, take the hook off): `prepare` writes it into `.claude/settings.json` (Round 1, step 4), committed. **Merge, never overwrite** — other suites' entries stay. Without the bridge, copy it **byte for byte from `align-hooks`**, `Memory guard`: a path in the project-memory directory → **block** (exit 2, routing message on stderr). Its refusal names the project graph and this `AGENTS.md`'s persistence section, and routes personal content through minding's entry without a personal address; a bare ban or a constructed mind locator is a projection defect. A harness flagging the write as self-modification: write anyway, name it, read back that it landed.

**The transition — take off the delivery's kinds.** The repository's own start, push or merge hook (`.claude/settings.json`, `settings.local.json`) or its own rituals plugin in `.opencode/plugins/` keeps the delivery silent on that kind; `prepare` names each in `left`. Take off only these kinds (in the plugin, the guard too): branches of other kinds (a merge gate…) and others' entries stay, and a plugin keeping them gets a name without `ritual`, by which the delivery tells it apart. A delivery older than this contract on this machine — or, the hooks being committed, on a teammate's as far as you know — keeps your own until it updates: say so in the report and in the alignment case. Tell it per harness: Claude Code — no `hooks/rituals.mjs` in its plugin cache; OpenCode — the plugin `~/.config/opencode/plugins/verstak.js` carries a `VERSION` below 3.27.0.

Also: **`PostToolUse` `Write|Edit` — spec-write** (full interop only): a design/spec-looking path → design is recorded in the graph; **branch freshness** — offer a pre-push hook (both `align-hooks`).

OpenCode: a plugin still standing in `.opencode/plugins/` and subscribed to the event stream is checked from the repo root with `node ~/.verstak-bridge/verstak-bridge.mjs check-rituals` every run: exit 1 → each line names plugin, problem, fix — rewrite, rerun, report. Checker missing → read each plugin against `align-harness-surfaces` yourself; say it didn't run.

Self-check: no start, push or merge hook and no rituals plugin of your own in the repository — or the report names why they stand (an older delivery); branches of other kinds they held are intact; one memory guard on a matcher covering Write and Edit while `guard` is on (a guard on a narrower matcher counts for none: widen it, or remove it and keep `prepare`'s), none when the field leaves it out; retired ones of yours (a `Stop` guard, a writing-moment pointer on write tools) removed; spec-write **iff** interop is `full`; `check-rituals` clean; no one else's entry lost. Exercise the memory guard without executing a write: the Claude Code shell command receives tool-input JSON for a forbidden memory path and an allowed repository path, exits 2/0 respectively; its refusal routes personal content through minding and contains no constructed or stored mind address. This checks the projected guard, not a live harness loading it; presence of an older hook does not pass.

### Step 5 — Repository hygiene
- Commit `.claude/settings.json`; ignore `.claude/settings.local.json`, `.worktrees/` (branch worktrees) and your eight role files by name in `.claude/agents/` and `.opencode/agents/` (a projection on the machine with the person's model, Step 6; others' agents in those directories untouched); under a broad `.claude/` ignore add `!.claude/settings.json`. Your role files already tracked → `git rm --cached` by the same names; the files stay on disk. Check `git check-ignore -v .claude/settings.json .claude/settings.local.json .worktrees/x .claude/agents/reviewer.md .opencode/agents/reviewer.md`, and that `git ls-files` names none of your eight. Every gate tool that walks the disk rather than git (ESLint flat config, vitest, jest, a formatter without its own ignore file) must exclude `.worktrees/` too: add the exclusion to its config and check by running the gate from the main checkout with a sibling tree present.
