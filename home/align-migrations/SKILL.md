# Migrations: the support boundary and legacy content

Read whole before the first mutation of a repository whose cover's `contract` is below `16`, missing, invalid or ambiguous, whose cover has an older form, or whose files show legacy content named below — at `16` too: the number doesn't replace the check of content (**align**, `Contract`). Name the starting contract in the report, or that it is unknown — never substitute `11`. Another delivery's cover does not become ours by this file; a contract above `16` is never lowered nor called unsupported — update the delivery. The live rules the content lands on — Step 4's transition, Step 5's hygiene, Step 6's roles, Step 7's cover — are the method's; this file carries only what the old form was and where its content goes. Content transfers before anything is deleted.

## 10 and below — a full run by current sources
The chain of moves from older contracts no longer applies. Run both rounds and every step of the current method against their sources; a full run is not "wipe it and start over". Before an edit, read the old config, the authored constraints, the role file tails and the hooks; re-project what is derived, keep the authored judgment, resolve a contradiction by Step 1. Others' hooks stay byte for byte; your own old ones and the memory guard: Step 4, `The transition`.

At start, in `doctor` or in `prepare` the delivery warns once at that entry, not on every command or frame: "Contract N is no longer supported; old hooks have not been removed. Run a full verstak align to contract 16; rituals will be accepted after verification". Codex and pi have no shipped start hook: there the warning comes through `doctor` and `prepare`. A missing or ambiguous number is unknown, not proof of an unsupported contract. Step 7 writes `16` only after the run's checks, never to silence the warning.

## 11 → 12
**align**, `From contract 11`. The move does not replace the passes over the whole artifact (Step 7).

## 12 → 13
**align**, `From contract 12`: the delegation role files re-projected, their tails kept.

## 13 → 14
**align**, `From contract 13`: the `deputy` role file projected in both harnesses and ignored by name; the other eight stay as they are.

## 14 → 15
**align**, `From contract 14`: all nine role files' bodies re-projected in both harnesses, each keeping its model and tail.

## 15 → 16
**align**, `From contract 15`: the `Refused tools` line and the `permissions.deny` entry for `AskUserQuestion`, beside others' entries; the cover is raised only after Step 4's self-check of the blocking question tool. A `deny` that isn't a list of strings, or `permissions` that isn't a map, is never rewritten: name it in the case and leave it to the person.

## Legacy content — at 16 too
Found old content → check it by the current steps; never run a retired chain:
- Own rituals (start, push or merge hooks, a `*ritual*` plugin, a `Stop` guard, a writing-moment pointer on write tools) → **align**, `Own rituals`, and Step 4, `The transition`; others' entries and other kinds stay.
- Flat cover slots, a `Cover` section or table, the stamp line at the file's end → **align**, `An older cover`. Unknown addresses are not guessed; what the bridge leaves in `left` is the model's work, not a reason to raise the number.
- A Reality table in `AGENTS.md`, a promised memory stub or an older guard refusal → Steps 4–7; no role tail or carrier is lost. An older form is no licence to delete a file whole.

## A searcher role file
The delegation roles are nine (Step 6). Project `weaver`, `recaller`, `ingester` and `deputy` in both harnesses and add them to `.gitignore` by name; delete both of your own `searcher` files and drop them from `.gitignore` (graph search is now `recaller`, for the recall ladder); re-project `designer`'s body, which no longer writes the graph — the volume edit of touched nodes is `weaver`'s, a story's intake `ingester`'s. Each file's tail in `Role file tails` carries over; a `searcher` tail goes to `recaller` where it still applies, else is named in the report.

## Role files in the index
Your role files leave the index and go into `.gitignore` by name — the files stay on disk, others' agents untouched (Step 5); every other clone loses them on its next pull, so say it in the alignment case and the PR body: a receiving copy saves its role files before pulling and puts them back (they are ignored then), else re-projects them by Step 6; each file's repository tail moves into `AGENTS.md`, section `Role file tails`, and its model comes from the person's preferences (Step 6).

## A Cross-project memory slot
Drop the cover's `Cross-project memory` slot and its source line — personal memory has no place in `AGENTS.md` (Step 1, `No personal memory in AGENTS.md`).

## Old questionnaire
An older cover's `Agreement` or hole names a node (`#N`), at any contract → `verstak_look`: answers → `Project` values; open ones → `open`, the question a message in the case. Release the node (`visarjana`, reasoning "moved to case #N") once the answers stand in the file or the case, not before; not yours → message its author.

## Legacy sections
Sections the template no longer has (`Session lifecycle`, reviews, branches, principles, integration scope, external surfaces, the feedback-reflection region, the `Cross-project memory` slot and its source) → delete, **code-work** and `verstak` own them; a repo fact inside (hook paths, forge) → its slot; a deliberate deviation or a consumer no graph arrow reaches (another instance) → `Local overrides` with its reason. Other content with no slot → "Code conventions" or `Local overrides`; a Reality table in `AGENTS.md` moves to `REALITY.md` row by row, its dated observations to graph nodes; a substantive `CLAUDE.md` merges in and becomes the pointer; `Layout` files keep their content, links checked; `nks_*` names become `verstak_*`.

A raised counter calls a repository back to a run; it does not prove the repository was re-aligned. The preservation of hooks and a live service start are checked apart from a green bundle check.
